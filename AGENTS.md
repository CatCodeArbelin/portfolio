# AGENTS.md

## Рабочий процесс

* Работай строго по этапам из `SPEC.md`.
* Не переходи к следующему этапу без подтверждения пользователя.
* Перед изменениями изучи текущую структуру проекта и существующий код.
* Не ломай уже работающий функционал.
* Не создавай пустые файлы и мёртвый код ради будущих этапов.
* Не добавляй новые production-зависимости без необходимости.
* Не оставляй TODO вместо работающей реализации.
* Не заявляй в README о функционале, который ещё не реализован.

## Качество кода

* Соблюдай DRY, KISS и YAGNI.
* Разделяй ответственность модулей.
* Используй понятные имена функций и переменных.
* Добавляй короткие русскоязычные docstring для backend-функций, сервисов и классов.
* Добавляй комментарии только там, где логика неочевидна.
* Не коммить секреты, токены и `.env`.

## Проверки перед PR

Перед открытием pull request обязательно запусти доступные проверки:

```bash
docker compose config
docker compose up --build -d
curl --fail http://localhost/api/v1/health
docker compose down
```

Backend:

```bash
cd backend
python -m compileall app
ruff check .
pytest
```

Frontend:

```bash
cd frontend
npm run build
npm run typecheck
```

Если команда ещё не реализована на текущем этапе — честно укажи это в отчёте, но не подменяй её фиктивной проверкой.

## Отчёт после этапа

После завершения этапа:

1. Перечисли изменённые файлы.
2. Перечисли выполненные команды.
3. Укажи exit code каждой проверки.
4. Кратко опиши реализованный функционал.
5. Отдельно перечисли ограничения и незавершённые пункты.
6. После каждого завершённого этапа обнови `PROGRESS.md`: отметь выполненный этап как [x] и оставь следующие этапы незавершёнными.
7. Создай отдельную ветку и pull request.
8. Не выполняй merge самостоятельно.
